# Архитектура

## Пайплайн распознавания (`ML service/`)

```
фото
 │
 ├─[1] кроп центральной бутылки ── YOLO (yolo11n, COCO bottle)
 │        │
 │        ├─[2] кроп этикетки ──── YOLO (label_det_best.pt, дообучен на этикетки)
 │        │        │
 │        │        └─[3] постпроцессинг: выравнивание кропа этикетки по 4 углам
 │        │                 │
 ▼        ▼        ▼        │
[4] retrieval: SigLIP2 → pgvector (cosine) → top-K визуальных кандидатов
 │                          │
 ▼                          ▼
[5] OCR-rerank: VLM читает выровненную этикетку → поля → CsvMatcher переставляет кандидатов
 │
 ▼
[6] гейт «есть в каталоге» → slug + карточка  |  «похожие вина»
```

| # | Этап | Где | Что делает |
|---|---|---|---|
| 1 | Кроп бутылки | `crop.py` `BottleCropper` | YOLO находит бутылки, берётся крупная и ближайшая к центру кадра; фон и соседи отрезаются |
| 2 | Кроп этикетки | `crop.py` `LabelCropper` | второй YOLO ищет этикетку внутри кропа бутылки; не нашёл — дальше идёт кроп бутылки |
| 3 | Выравнивание | `label_align.py` | внутри бокса этикетки ищутся 4 угла, этикетка «распрямляется» в прямоугольник (`cv2.warpPerspective`), как в сканерах документов. Не нашлись углы — обычный кроп бокса |
| 4 | Retrieval | `encoder.py`, `db.py` | SigLIP2 (`siglip2-base-patch16-256`, 768-d, L2) → косинус в pgvector, max по slug (у вина несколько фото). Две ветки: бутылка и этикетка, берётся ветка с бо́льшим top-1. Выход — шорт-лист top-K (`top_k: 6`) |
| 5 | OCR-rerank | `ocr_rerank.py` | см. ниже |
| 6 | Гейт | `app.py` `_gate` | см. ниже |

### OCR-rerank

1. **OCR** (`OcrExtractor`): VLM `google/gemini-2.5-flash` (OpenRouter) получает выровненный кроп
   этикетки и возвращает JSON: винодельня, сорт, цвет, сахар, игристое/тихое, линейка, год, доп. текст.
   Если сорт не прочитан или его нет в словаре каталога — второй проход по кропу бутылки, поля объединяются.
2. **CsvMatcher**: каждой записи каталога (`found_in_catalog_corrected.csv` + OCR-разметка каталожных фото)
   считается взвешенное совпадение полей. Веса: сорт 0.24, линейка 0.20, винодельня / цвет / сахар по 0.15,
   игристое 0.07, год и доп. текст по 0.02.
3. **Перестановка**: кандидаты, похожие по тексту, поднимаются выше. Ответ retrieval заменяется, только если
   лучший по тексту кандидат опережает его на `decision_margin` (0.35).
4. **Близкие негативы**: вина одной линейки с почти одинаковой этикеткой (другой сорт, сахар или цвет)
   визуально неотличимы, но по тексту расходятся в поле-дискриминаторе — CsvMatcher опускает их вниз.
5. **Визуальная проверка** (`VisualVerifier`): косинус запроса с эталонным фото нового кандидата.
   Сейчас только пишется в ответ, решение не блокирует.

### Гейт «есть в каталоге»

| top-1 score retrieval | Результат |
|---|---|
| ≥ 0.81 | карточка |
| < 0.70 | нет в каталоге → похожие вина + аналоги |
| 0.70–0.81 | карточка, только если OCR подтвердил кандидата (уверенность ≥ 0.80) |

Гейт действует на `/v1/search` (UI). `/v1/eval/predict` всегда отдаёт лучший slug.

## Сервисы

```
браузер (профиль сомелье — localStorage, сканы — sessionStorage)
   │
https (Caddy :443) ─► web (Nuxt SPA + Nitro BFF :3000)
                         ├─► ml        (FastAPI :8080)  кроп → SigLIP2 → pgvector → OCR-rerank ◄── eval
                         └─► sommelier (FastAPI :8090)  LLM-диалог, STT, скоринг вино ↔ профиль
                                   │
                          db (Postgres + pgvector)
```

| Сервис | Роль |
|---|---|
| `ml` | распознавание (пайплайн выше) |
| `sommelier` | фича после поиска: диалог (текст/голос) → профиль вкуса → вердикт по каждому скану, подбор, аналоги |
| `web` | UI и BFF: `/api/scan`, `/api/wine/:slug`, `/api/chat`, `/api/stt` … |
| `db` | `wines` (карточки), `wine_vectors` (векторы, ключ = модель, `#label` — ветка этикетки), `wine_profiles` (сомелье) |
| `fetch`, `db-init` | одноразовые: скачать данные/модели, восстановить дамп индекса |
| `eval` | прогон скрипта организаторов против `ml` |

## Решения

- Все параметры распознавания — в `config/pipeline.yaml`.
- Индекс хранится в pgvector и приезжает готовым дампом; пересборка — только при смене энкодера или кропа индекса.
- Кроп запроса настроен под фото с полки, кроп индекса — под студийные фото каталога (`query_crop_*` против `crop_*`).
- Скоринг сомелье детерминированный, LLM только переводит разговор в профиль.
- Сервисы без состояния: профиль и история — в браузере.
- Оценка изолирована от LLM сомелье: `/v1/eval/predict` не зависит от `sommelier`.
