# 27. Гейт «вино есть в каталоге»: сценарий похожих вместо всегда-карточки

## Проблема

Сервис **всегда** отдавал top-1 слаг: даже если сфотографировать вино, которого в каталоге нет
(иностранное или другая линейка/год), UI открывал карточку «ближайшего» вина. При этом сценарий
«точного совпадения нет → похожие по этикетке + аналоги других виноделен» в вебе реализован и
включается по флагу `in_catalog=false` (`web/server/api/scan.post.ts` → экран `/no-match`).

Причина: гейт был однопороговым — `in_catalog = top1_score >= 0.75`, без учёта отрыва и без
текстовых свидетельств.

## Семантика истины (уточнение организаторов)

* **год/крепость** (хвостовое число слага) на тождество **не влияют**: если винтажа с таким годом
  нет в каталоге, но вино во всём остальном то же — это **то же вино** (карточка уместна);
* **сорт, цвет, сахар/тип, линейка** — влияют: `…-beloe-suhoe-12` и `…-beloe-polusladkoe-12` это
  **разные** вина, даже если этикетка похожа.

Реализовано в `ML evaluation/wine_identity.py` (`same_wine()`), самотесты — `--selftest`.
По этому правилу пересчитаны и метрики качества (отчёт 26), и верность карточек в этом отчёте.

## Данные калибровки

* **позитивы — 188**: 185 фото (62 + eval2) + **3 фото из `data/negatives`, которые по правилу
  оказались тем же вином с другим годом** (у них совпали цвет/сахар/линейка с каталожным вином);
* **негативы — 8**: остальные фото `data/negatives` — иностранные марки и вина, у которых цвет или
  сахар/тип **конфликтуют** с ближайшим каталожным вином (классификация —
  `reports/27_gate_negatives/neg_classified.json`, скрипт `/tmp/classify_neg.py`).

Что важно в данных: у негативов **крошечный отрыв** top1−top2 (0.003–0.034 против медианы 0.025–0.039
у позитивов), а VLM читает на их этикетках либо чужие бренды (`ALVEUS`, `CASA LORETTI`,
`CHÂTEAU PINOT`, `KD`, `Mogzauri`, `Gusto`), либо нечитаемые поля (`csv_ambiguous` у 7 из 11).

## Что не сработало

| правило | негативы приняты | позитивы потеряли | F1 |
|---|---|---|---|
| `top1 >= 0.75` (было) | **4 / 8** ✗ | 7 | 0.8293 |
| `top1 >= 0.75 и margin >= 0.015` | 1 / 8 | ~63 ✗✗ | ~0.73 |
| `top1 >= 0.80` | 1 / 8 | 27 | 0.788 |
| `top1 >= 0.82` | 0 / 8 | 41 ✗ | 0.758 |

Один визуальный порог отделяет негативы ценой ~20% карточек (распределения пересекаются: самый
«похожий» негатив имеет top1 = 0.8085, у верных позитивов бывает 0.72–0.79), а `margin` слишком
дорог — у near-dup серий отрыв мал даже когда top-1 верен.

## Решение: визуальный порог + подтверждение по OCR

```
карточка (in_catalog = true), если
    top1 >= HI (0.81)                                    — сильное визуальное совпадение
или top1 >= LO (0.70) и OCR уверенно подтвердил кандидата:
        stage = ocr_rerank  и csv_confidence >= 0.80     — OCR сам переставил ответ на него
        reason = csv_agrees и csv_confidence >= 0.60     — OCR согласился с ответом retrieval
иначе — «точного совпадения нет» (UI показывает похожие + аналоги)
```

Реализация: `ML service/app.py::_gate()`; пороги в `config/pipeline.yaml` — `retrieval.thresh_score`
(HI), `retrieval.thresh_score_lo` (LO), `ocr.confirm_confidence`, `csv_match.agree_confidence`.
В ответе `/v1/search` появился `gate_reason` (`visual_hi` / `ocr_confirms` / `ocr_agrees` /
`ocr_not_confirmed` / `low_score`).

Почему так работает: у иностранных вин VLM читает **другой** бренд/сорт и матча в каталоге нет
(`csv_ambiguous`) — карточка не показывается, хотя визуально вино «похоже». А у настоящих
каталожных вин с невысоким визуальным score OCR обычно как раз согласен или уверенно уточняет —
карточка сохраняется (37 фото из 188 имеют top1 < 0.81; OCR-путь сохраняет карточку 12 из них,
11 — с верным ответом).

## Метрики до/после (188 позитивов + 8 негативов)

| | было (`top1>=0.75`) | стало (HI/LO + OCR) |
|---|---|---|
| негативов принято (ложная карточка) | 4 / 8 | **0 / 8** ✓ |
| позитивов с карточкой | 181 / 188 (96%) | 165 / 188 (88%) |
| из потерянных — верных карточек | 5 из 7 | 9 из 23 (14 — уже неверные ответы) |
| TP / FP / FN | 136 / 49 / 7 | 132 / 33 / 23 |
| precision карточек | 0.7351 | **0.8000** |
| recall карточек | 0.9510 | 0.8516 |
| **F1 решения «отдать карточку»** | 0.8293 | **0.8250** |

Итог: точность карточек +6.5 п.п., F1 не изменился в пределах шума (−0.4 п.п.), ложных карточек для
вин вне каталога — ноль (сценарий похожих срабатывает у всех 8). Цена — 8% фото, которые теперь
показывают похожих вместо карточки; больше половины из них (13/23) и раньше давали неверную карточку.

## Ограничения

* Негативов немного (8 настоящих + 3 «другого года»); порог HI стоит у нижнего дециля позитивов —
  при росте негативного набора калибровку надо повторить (скрипты в репозитории).
* OCR-путь зависит от доступности VLM (OpenRouter): без ключа `stage/reason/csv_*` пустые, гейт
  становится строгим (только `visual_hi`) — похожие включаются чаще, ложных карточек нет.
* Классификация «то же вино / другое вино» для негативов сделана по цвету и сахару/типу, которые
  прочитал VLM; для 2 фото сахар на этикетке не указан — там вердикт основан на бренде (латиница
  против кириллицы в каталоге), это стоит перепроверить вручную.
