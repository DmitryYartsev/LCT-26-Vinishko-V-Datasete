# Пайплайн распознавания

Код — `ML service/`, параметры — `config/pipeline.yaml`. Общая схема — [ARCHITECTURE.md](../ARCHITECTURE.md).

## 1. Кроп бутылки — `crop.py`

YOLO `yolo11n.pt` (COCO, класс `bottle`). Из нескольких бутылок выбирается крупная и центральная,
бокс расширяется на `crop_margin`.

Политика кропа у индекса и запроса разная:

| | Индекс (студийные фото) | Запрос (фото с полки) |
|---|---|---|
| выбор бокса | `big_center` | `big_center_border` — штраф за срезанный рамкой бокс и небутылочные пропорции |
| порог детектора | 0.25 | 0.10 + отсев боксов меньше 12% кадра |
| бутылка не найдена | всё фото | ищем этикетку прямо на фото |

Кроп запроса можно менять без пересборки индекса, кроп индекса — только с пересборкой.

## 2. Кроп этикетки — `crop.py`

Дообученный YOLO `label_det_best.pt` внутри кропа бутылки. Не нашёл — вместо этикетки идёт кроп бутылки.

## 3. Выравнивание этикетки — `label_align.py`

Внутри бокса ищутся 4 угла этикетки (Canny/Оцу → контуры → `approxPolyDP`, запасной вариант —
`minAreaRect`), затем `cv2.warpPerspective` распрямляет её в прямоугольник. Углы не нашлись — кроп бокса.
Выровненный кроп идёт в OCR; в retrieval ветка этикетки использует кроп бокса (`retrieval.label_align: false`).

## 4. Retrieval — `encoder.py`, `db.py`

- SigLIP2 `siglip2-base-patch16-256` → вектор 768, L2-норма.
- pgvector: `wine_vectors`, по вектору на каждое фото вина; поиск — косинус, агрегация max по slug.
- Две ветки: кроп бутылки (ключ = модель) и кроп этикетки (ключ `…#label`). Побеждает ветка с большим top-1.
- Шорт-лист — top-K (`top_k: 6`), `margin` = top1 − top2.

## 5. OCR-rerank — `ocr_rerank.py`

**Чтение** (`OcrExtractor`). VLM (`ocr.model`, по умолчанию `google/gemini-2.5-flash`) получает
выровненный кроп этикетки, увеличенный до `min_side` (800 px) и ограниченный `max_side` (1400 px).
Промпт — `prompts_wine_match.txt`, ответ — JSON:

`winery`, `grape`, `color`, `sugar`, `sparkling`, `line`, `year`, `additional_text`.

Если сорт не прочитан или его нет в словаре каталога — второй вызов по кропу бутылки, поля сливаются
(`retry_on_poor_fields`).

**Сопоставление** (`CsvMatcher`). Для каждой записи каталога (`data/found_in_catalog_corrected.csv`,
дополнена OCR-разметкой каталожных фото `data/catalog_ocr_fields.csv`) считается уверенность — взвешенная
доля совпавших полей:

| Поле | Вес |
|---|---|
| сорт | 0.24 |
| линейка | 0.20 |
| винодельня, цвет, сахар | 0.15 |
| игристое / тихое | 0.07 |
| год, доп. текст | 0.02 |

Поле, которого нет в записи каталога, даёт 0.5 (нейтрально). Сравнение слов — нечёткое, с транслитом.

**Перестановка** (`decide`). Кандидаты сортируются по уверенности. Ответ retrieval заменяется лучшим
по тексту кандидатом, если:

- уверенность ≥ 0.35 (`min_score`, `ocr.min_confidence`);
- отрыв от уверенности ответа retrieval ≥ `decision_margin` (0.35).

Так близкие негативы — вина одной линейки с почти одинаковой этикеткой, но другим сортом, сахаром или
цветом — уходят вниз, а визуально похожий кандидат с совпадающим текстом поднимается.

**Визуальная проверка** (`VisualVerifier`). Если ответ заменён — косинус кропа запроса с эталонным фото
кандидата (`data/start_photos`). По умолчанию только диагностика (`visual.block_on_mismatch: false`).

## 6. Гейт «есть в каталоге» — `app.py` `_gate`

| Условие | `in_catalog` | `gate_reason` |
|---|---|---|
| top-1 ≥ `thresh_score` (0.81) | true | `visual_hi` |
| top-1 < `thresh_score_lo` (0.70) | false | `low_score` |
| между ними, OCR переставил ответ с уверенностью ≥ 0.80 | true | `ocr_confirms` |
| между ними, OCR согласен с retrieval с уверенностью ≥ 0.80 | true | `ocr_agrees` |
| между ними, иначе | false | `ocr_not_confirmed` |

`in_catalog: false` → UI показывает похожие по этикетке и аналоги от сомелье.
`/v1/eval/predict` гейт не применяет и всегда отдаёт итоговый slug (кроме `eval_abstain: true`).

## Поля ответа `/v1/search` по этапам

| Поле | Этап |
|---|---|
| `branch`, `branches` | 4 — какая ветка победила |
| `results`, `top1`, `confidence` | 4 — шорт-лист, score, margin |
| `ocr_input`, `ocr_fields` | 5 — что ушло в VLM и что прочитано |
| `top_candidates`, `csv_confidence`, `csv_margin` | 5 — сопоставление |
| `pre_ocr_slug`, `final_slug`, `stage` | 5 — `stage: ocr_rerank`, если ответ заменён |
| `visual_similarity` | 5 — визуальная проверка |
| `in_catalog`, `gate_reason` | 6 |
