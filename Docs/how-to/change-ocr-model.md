# Смена модели, читающей этикетки

Чтение этикетки выполняет внешняя vision-модель на OpenRouter. Модель задаётся одной строкой в
конфиге, локальных весов для неё не требуется.

## Когда это нужно

* Нужно быстрее или дешевле — модели различаются временем ответа и ценой за токены.
* Нужно точнее на ваших фотографиях — качество чтения зависит от модели и от того, как на ваших
  снимках выглядят даты, сорта и линейки.
* Нужно выключить чтение этикетки совсем — например, чтобы работать без интернета и внешних ключей.

## Шаг 1. Убедиться, что модель доступна с вашим ключом

```bash
source .env 2>/dev/null; curl -s https://openrouter.ai/api/v1/models \
  -H "Authorization: Bearer ${OPENROUTER_API_KEY//\"/}" \
  | python3 -c "import json,sys; print('\n'.join(m['id'] for m in json.load(sys.stdin)['data'] if 'gemini' in m['id']))"
```

Подставьте в фильтр нужное семейство. Если список пуст или запрос падает — проверьте ключ.

## Шаг 2. Поменять модель в конфиге

`config/pipeline.yaml`, секция `ocr`:

```yaml
ocr:
  enabled: true
  model: google/gemini-2.5-flash      # сюда пишется id модели на OpenRouter
```

## Шаг 3. Перезапустить сервис

Конфиг смонтирован в контейнер, поэтому достаточно перезапуска:

```bash
docker compose restart ml
docker compose logs -f ml | grep -i 'OCR-rerank'
```

В логе должна появиться строка вида `[startup] OCR-rerank: model=<ваша модель>, refs=2107`.

## Шаг 4. Проверить на фотографии

```bash
curl -s -F "image=@photo.jpg" http://localhost:8080/v1/search \
  | python3 -m json.tool | grep -E '"(stage|ocr_input|ocr_error|csv_confidence)"'
```

* `ocr_input` не пустой, `ocr_error: null` — модель вызвалась и что-то прочитала;
* `stage: ocr_rerank` — модель переставила ответ визуального поиска;
* `stage: retrieval` и непустой `csv_confidence` — модель отработала, но согласилась с поиском.

Проверьте также `/health`: поле `ocr_model` показывает активную модель.

## Если решите выключить чтение этикетки

```yaml
ocr:
  enabled: false
```

Сервис будет отвечать только визуальным поиском: быстрее и без внешних вызовов, но решения в
середине рабочего диапазона порогов станут «вина нет в каталоге» — см.
[../explanation/catalog-gate.md](../explanation/catalog-gate.md).

## Что ещё стоит посмотреть при смене модели

| Параметр | Зачем |
|---|---|
| `ocr.max_tokens`, `ocr.timeout` | если модель отвечает длинно или медленно |
| `ocr.retry_on_poor_fields` | повторный проход по кропу бутылки, когда прочитано мало полей |
| `csv_match.decision_margin` | с каким запасом ответ модели вытесняет ответ визуального поиска |
| `ocr.confirm_confidence`, `csv_match.agree_confidence` | пороги подтверждения карточки в середине диапазона |

## Как понять, стало ли лучше

Пройдите [../tutorials/first-evaluation.md](../tutorials/first-evaluation.md) на своём наборе
фотографий дважды: с прежней и с новой моделью. Сравнивайте долю верных первых ответов и время
на фотографию — и решайте.
