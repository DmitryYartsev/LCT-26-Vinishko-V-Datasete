# Диагностика

Быстрый набор команд, с которого стоит начинать в любом случае:

```bash
docker compose ps                                  # кто запущен и кто healthy
docker compose logs --tail=50 ml                   # прогрев, чтение этикеток, ошибки
docker compose logs --tail=20 web                  # ошибки интерфейса и его запросов
docker compose stats --no-stream                   # процессор и память по контейнерам
curl -s localhost:8080/health                      # состояние сервиса распознавания
curl -s -F "image=@photo.jpg" localhost:8080/v1/search | python3 -m json.tool | head -40
```

## Симптом: интерфейс пишет «не удалось распознать фото»

1. Проверьте, готов ли сервис распознавания: `docker compose ps` (нужно `ml = healthy`) и
   `curl -s localhost:8080/health`.
2. Повторите скан напрямую, минуя интерфейс:

   ```bash
   curl -s -o /tmp/r.json -w 'HTTP %{http_code}\n' -F "image=@photo.jpg" localhost:8080/v1/search
   cat /tmp/r.json | head -c 300
   ```

   * `400` и `{"detail":"bad image"}` — файл не читается как изображение (частый случай — HEIC
     с iPhone: конвертируйте в JPEG/PNG/WebP);
   * `200` с полным ответом — проблема на стороне интерфейса, смотрите `docker compose logs web`;
   * соединение не устанавливается — `ml` не поднялся или перезапускается, нужны его логи.
3. Если в ответе `"in_catalog": false` — это не ошибка, а сценарий «похожие вина». Смотрите
   `gate_reason`, чтобы понять решение.

## Симптом: кнопка с примером или камера «не реагирует»

1. Проверьте, что интерфейс отдаёт страницу и картинку примера:

   ```bash
   curl -so /dev/null -w '%{http_code}\n' localhost:3000/
   curl -sI localhost:3000/img/sample-label.jpg | head -3      # ожидаем 200 и image/jpeg
   ```

2. Откройте в браузере консоль и вкладку сети: если запросов к `/api/scan` нет вообще —
   отклонён сам файл (не картинка по типу); если скрипты страницы не загрузились (404 на
   `/_nuxt/...`) — обновите страницу с очисткой кеша (`Cmd/Ctrl + Shift + R`).
3. После пересборки интерфейса браузер иногда держит старые скрипты: очистите данные сайта для
   этого адреса.

## Симптом: `ml` долго не становится `healthy`

Смотрите логи: `docker compose logs -f ml`.

| В логе | Что происходит |
|---|---|
| `[warmup] индексы '…' уже есть, пропускаю` | норма: индекс готов, сервис поднимается секунды |
| `[warmup] эмбеддинг N фото` | векторы считаются с нуля — это десятки минут; не перезапускайте контейнер |
| `[preflight] НЕ ХВАТАЕТ ФАЙЛОВ` | не скачались данные или модели: `docker compose run --rm fetch --status` |
| `bad image`, traceback по OCR | проблема только в чтении этикеток, визуальный поиск при этом работает |
| контейнер циклично перезапускается | не хватает памяти: `docker compose stats --no-stream` |

## Симптом: `db-init` пишет «дампа нет»

Значит не скачался `deploy/archives/pgvector.dump` — сервис соберёт индекс сам, это долго.
Докачайте дамп и перезапустите:

```bash
docker compose run --rm fetch --only dump
docker compose restart ml
```

## Симптом: заняты порты

```bash
docker compose ps
lsof -nP -iTCP:3000 -iTCP:8080 -iTCP:8090 -sTCP:LISTEN       # macOS/Linux
```

Обычно это ранее запущенный стенд: остановите его (`docker compose down` в его каталоге), либо
поменяйте наружные порты через `.env` (`HTTP_PORT`, `HTTPS_PORT`) — порты `3000/8080/8090`
заданы в compose и при желании правятся там.

## Симптом: сканы отвечают, но всегда «вина нет в каталоге»

Проверьте, работает ли чтение этикеток: `/health` → `ocr_rerank` и `ocr_model`. Если ключ
`OPENROUTER_API_KEY` не задан или неверный, ответы в середине диапазона сходства не получают
подтверждения и трактуются как «нет в каталоге». Проверка ключа:

```bash
curl -s localhost:8090/health           # поле api_key: должно быть true
docker compose logs ml | grep -i ocr | tail -20
```

## Симптом: скан идёт минуту и больше

Основное время занимает внешний вызов чтения этикетки. Что смотреть: `ocr.timeout`, `ocr.retries`,
`ocr.max_tokens`; помогает более быстрая модель (см. [change-ocr-model.md](change-ocr-model.md)).
Первый скан после старта всегда медленнее — прогреваются модели.

## Симптом: не работает голосовой ввод

Микрофон в браузере доступен только на защищённом соединении, то есть по HTTPS или на
`localhost`. Откройте сайт по `https://<PUBLIC_HOST>` (см. [deploy-on-server.md](deploy-on-server.md))
и убедитесь, что ключ задан: сомелье отдаёт `api_key: true` в `/health`.

## Симптом: у вина нет фото

`GET /ref/{slug}` вернул `404` — значит в фотокаталоге нет папки `filtered/<slug>`: проверьте, что
фотокаталог скачан (`docker compose run --rm fetch --status`) и что slug совпадает с папкой.

## Симптом: заканчивается место на диске

```bash
docker system df
docker image prune -f          # убрать неиспользуемые образы
```

Модели (≈1.4 ГБ), данные (≈0.4 ГБ) и том с векторами удалять не нужно — они нужны сервису.
