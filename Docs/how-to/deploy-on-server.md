# Развёртывание на сервере

## Что нужно

* Linux-сервер с Docker и плагином `docker compose`.
* Ресурсы: 4 ядра, от 8 ГБ RAM, от 30 ГБ диска (модели ≈1.4 ГБ, данные ≈0.4 ГБ, образы ≈3 ГБ).
* Ключ OpenRouter для чтения этикеток, диалога и распознавания речи.
* Для голосового ввода нужен HTTPS: браузер даёт микрофон только на защищённом соединении.
  По голому `http://<ip>:3000` микрофон работать не будет.

## Шаг 1. Подготовить код и окружение

```bash
git clone <repo> && cd LCT-26-Vinishko-V-Datasete
cp .env.example .env
```

В `.env` заполните ключ:

```
OPENROUTER_API_KEY="sk-or-v1..."
```

Если сайт будут открывать не на `localhost`, добавьте адрес, по которому он доступен: по умолчанию
Caddy отдаёт сайт как `localhost`, а на сервере это нужно заменить.

```
PUBLIC_HOST=1-2-3-4.sslip.io      # или IP сервера: 155.138.200.98
```

`PUBLIC_HOST` — адрес, по которому открывают сайт (по умолчанию `localhost`):

| Значение | Сертификат | Что увидит браузер |
|---|---|---|
| домен, смотрящий на сервер (в том числе `1-2-3-4.sslip.io` для IP `1.2.3.4`) | Let's Encrypt | обычный HTTPS, нужны открытые порты 80 и 443 |
| IP-адрес или `localhost` | внутренний CA | один раз предупреждение о сертификате, дальше нормально |

## Шаг 2. Запустить

```bash
docker compose up -d --build
```

Первый запуск скачивает модели и данные. Готовность проверяется так:

```bash
docker compose ps                        # ждём ml = healthy
curl -s localhost:8080/health            # status ok, wines 2107
```

## Шаг 3. Открыть и проверить

Откройте `https://<PUBLIC_HOST>` — это интерфейс. Прогоните один скан и, если он открыт по
домену, проверьте голосовой ввод в панели сомелье.

Наружу нужны только 80 и 443 (их публикует контейнер `https`). Порты интерфейса и сервисов
(`3000`, `8080`, `8090`) публикуются для отладки — при желании закройте их файрволом.

## Сколько занимает времени

| Этап | Время |
|---|---|
| Скачивание данных, моделей и дампа индекса | минуты (≈2 ГБ) |
| Старт `ml` с готовым дампом индекса | 10–30 секунд |
| Старт `ml` без дампа (векторы считаются с нуля) | десятки минут, до часа на слабой машине |
| Первый скан после старта | на несколько секунд дольше последующих (прогрев) |

Сборка образов и прогрев сервиса конкурируют за CPU: на 4 ядрах не стоит запускать
`docker compose build` одновременно с первым прогревом `ml`.

## Обновление версии

```bash
git pull
docker compose up -d --build
```

Том с индексом сохраняется между перезапусками, поэтому повторного прогрева не будет.

## Чего избегать

* `docker compose down -v` — удаляет том с векторами индекса, после этого сервис считает их заново.
* Файл `.env` с ключом не должен попадать в git (он уже в `.gitignore`).
* Не менять политику кропа индекса (`crop_*` в конфиге) без пересборки индекса: иначе запрос и
  векторы каталога окажутся в разных условиях — см. [../how-to/update-catalog-and-index.md](../how-to/update-catalog-and-index.md).

## Проверки после развёртывания

| Проверка | Команда | Ожидание |
|---|---|---|
| Сервис распознавания | `curl -s localhost:8080/health` | `status ok`, `wines 2107`, `ocr_rerank true` |
| Интерфейс | `curl -so /dev/null -w '%{http_code}' localhost:3000/` | `200` |
| Скан | `curl -s -F image=@photo.jpg localhost:8080/v1/search` | JSON с `final_slug` и `elapsed_ms` |
| HTTPS | открыть `https://<PUBLIC_HOST>` | страница сканера |
| Сомелье | `curl -s localhost:8090/health` | `llm_model` и `api_key: true` |
| Использование ресурсов | `docker compose stats --no-stream` | в покое около 1 ГБ RAM |
