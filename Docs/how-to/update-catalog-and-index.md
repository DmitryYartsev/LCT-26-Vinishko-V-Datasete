# Обновление каталога и пересборка индекса

«Индекс» — это векторы всех фотографий каталога, лежащие в Postgres (таблица `wine_vectors`)
под ключом `retrieval.index_model`, и карточки вин в таблице `wines`. Поиск идёт только по
векторам с активным ключом.

## Когда нужно

* В каталог добавили вина или фотографии.
* Поменяли политику кропа **индекса** (`crop_*`, `label_*`, `label_align`) — тогда индекс обязан
  быть пересобран, иначе векторы каталога и фотография пользователя окажутся в разных условиях.
* Меняете модель энкодера (`retrieval.model`) или её бэкенд.
* Нужно перенести готовый индекс на другую машину.

## Обновить каталог

1. Добавьте фотографии: `filtered/<slug>/NN.webp` (несколько файлов на вино — только улучшает
   качество: вектор считается по каждому фото).
2. Добавьте карточку вина в `filtered/catalog.csv` — из неё заполняется таблица `wines`.
3. Для сопоставления по тексту этикетки добавьте запись и в `data/found_in_catalog_corrected.csv`
   (имя вина, винодельня, цвет, регион, сорт).

## Пересобрать векторы

```bash
docker compose exec ml python build_index.py --force
```

Без `--force` команда только проверяет наличие векторов и ничего не делает. Прогресс виден в логах:

```bash
docker compose logs -f ml | grep -E '\[warmup\]|\[startup\]'
```

Пересборка 2 108 фотографий занимает десятки минут и почти всё время держит процессор —
на 4 ядрах это может быть заметно долго. Пока команда идёт, сервис отвечает на запросы (поиск
работает и с частично обновлённым индексом), но качество в это время нестабильно.

## Проверить результат

```bash
docker compose exec db psql -U vino -d vino -c \
  "select model, count(*) from wine_vectors group by 1 order by 1;"
docker compose exec db psql -U vino -d vino -c "select * from models;"
curl -s localhost:8080/health
```

Ожидаемо: два ключа (обычный и `…#label`) с одинаковым числом векторов, обновлённое число вин
в `/health` (`wines`) и запись в `models` со свежим `built_at`.

## Сохранить индекс и перенести на другую машину

Собранный индекс удобно возить дампом — тогда на новой машине сервис поднимется за секунды,
а не за десятки минут.

```bash
# на машине, где индекс собран
docker compose exec -T db pg_dump -U vino -d vino -Fc -f /tmp/pgvector.dump
docker compose cp db:/tmp/pgvector.dump deploy/archives/pgvector.dump
```

На новой машине положите файл в `deploy/archives/pgvector.dump` и запустите `docker compose up`:
контейнер `db-init` восстановит его, если база пустая (иначе ничего не тронет — восстановление
идемпотентно).

## Чего не делать

* Не удаляйте том `pgdata` (`docker compose down -v`) до того, как сохранили дамп: вместе с ним
  уйдёт готовый индекс.
* Не меняйте политику кропа индекса во время работы сервиса: часть векторов окажется собранной по старой
  политике, часть — по новой. Если меняете — пересобирайте индекс целиком.
* Не меняйте `retrieval.index_model` вручную на другой ключ: поиск начнёт смотреть на пустой набор
  векторов и перестанет находить вина (в ответе `/v1/search` это видно как пустой `results`).
