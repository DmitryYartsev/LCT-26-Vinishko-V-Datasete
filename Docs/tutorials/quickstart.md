# Запуск и первое распознавание

За 15 минут вы поднимете сервис на своей машине и распознаете первое фото: увидите, как система
находит вино в каталоге и что происходит, когда вина в каталоге нет.

## Что понадобится

* Docker с поддержкой `docker compose`.
* ~6 ГБ свободного места (модели ≈1.4 ГБ, данные ≈0.4 ГБ, образы ≈3 ГБ).
* Доступ в интернет — первый запуск скачивает модели и данные.
* Ключ OpenRouter (<https://openrouter.ai/keys>) — если хотите, чтобы сервис читал текст этикетки.
  Без ключа всё поднимется, но распознавание будет только визуальным.

## Шаг 1. Получить код и настроить окружение

```bash
git clone <repo> && cd LCT-26-Vinishko-V-Datasete
cp .env.example .env
```

Откройте `.env` и вставьте ключ:

```
OPENROUTER_API_KEY="sk-or-v1..."
```

## Шаг 2. Запустить стек

```bash
docker compose up -d --build
```

Первый запуск качает модели и данные — это несколько минут. Дождитесь готовности сервиса:

```bash
docker compose ps
```

Нужно, чтобы у `ml` было `healthy`. Если он ещё `starting` — подождите: сервис загружает модели и
проверяет индекс. Быстрая проверка готовности:

```bash
curl -s localhost:8080/health
```

В ответе должно появиться `"status":"ok"`, `"wines":2107` и имя модели чтения этикетки.

## Шаг 3. Распознать первое фото в интерфейсе

Откройте <http://localhost:3000> и нажмите кнопку с примером этикетки. На телефоне можно снять
бутылку камерой прямо в сервисе или выбрать фото из галереи, на компьютере — загрузить файл.
Через несколько секунд появится карточка вина: название, винодельня, сорт, цвет, регион, описание.

Полезно посмотреть на альтернативы: если у сайдбара есть отладочная информация, вы увидите время
поиска и уверенность. Включить её можно так:

```bash
DEBUG_INFO=1 docker compose up -d web      # выключить: DEBUG_INFO=0 docker compose up -d web
```

## Шаг 4. Посмотреть «нет в каталоге»

Возьмите фотографию вина, которого нет в каталоге (например, любое иностранное вино). Вместо
карточки появится экран с похожими по этикетке винами и аналогами по стилю. Это ожидаемое
поведение: система не показывает карточку «ближайшего» вина, если уверена, что это не оно.

## Шаг 5. Проверить сервис напрямую

Интерфейс — не единственный вход; сервис распознавания можно дёрнуть напрямую:

```bash
curl -s -F "image=@moya-butylka.jpg" http://localhost:8080/v1/search | python3 -m json.tool
```

Обратите внимание на поля `in_catalog` (показывать карточку или похожие), `final_slug` (ответ),
`stage` (`retrieval` или `ocr_rerank` — кто дал ответ) и `elapsed_ms`.

## Чему вы научились

* Стек поднимается одной командой, готовность видна в `docker compose ps` и `/health`.
* Распознавание двухступенчатое, и ответ может прийти как от визуального поиска, так и от чтения
  этикетки.
* «Вино не найдено» — отдельный сценарий, а не ошибка.
