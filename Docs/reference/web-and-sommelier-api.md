# Справочник: роуты интерфейса и API сомелье

## Интерфейс (`web`, порт 3000)

Браузер общается только с этими роутами (Nuxt/Nitro, `/api/*`); они ходят в `ml` и `sommelier`
внутри docker-сети.

| Роут | Метод | Вход | Выход |
|---|---|---|---|
| `/api/scan` | POST | `multipart`: `image`, опционально `profile` (JSON) | см. ниже |
| `/api/wine/{slug}` | POST | `{profile}` | `{wine, match, alts, analogs}` |
| `/api/wines` | POST | `{slugs[]}` | карточки сканов сессии |
| `/api/chat` | POST | `{messages[], profile}` | `{reply, profile, picks, suggestions}` |
| `/api/stt` | POST | `multipart`: `audio` | `{text}` |
| `/api/ref/{slug}` | GET | `?h=` (высота превью) | изображение |
| `/api/stats` | GET | — | счётчики сервиса |

`/api/scan` — главный роут. Он отдаёт сокращённый ответ `ml`:

```json
{"in_catalog": false, "elapsed_ms": 12699,
 "confidence": {"top1_score": 0.7323, "margin": 0.0131, "thresholds": {"score": 0.81}},
 "top1": {"slug": "shato-ay-danil-bomond-aligote-beloe-suhoe-13", "score": 0.7323},
 "results": [{"slug": "...", "score": 0.7323}]}
```

Если вина в каталоге нет (`in_catalog: false`), к ответу добавляются два блока — за них отвечает
сомелье, и при его недоступности скан всё равно вернётся:

| Поле | Что это |
|---|---|
| `similar` | до пяти похожих по этикетке кандидатов с процентом сходства и вердиктом относительно профиля пользователя |
| `analogs` | до четырёх аналогов по стилю из других виноделен |

Ошибки: `400` — в запросе нет файла `image`.

## Сервис сомелье (`sommelier`, порт 8090)

Диалог, речь, детерминированный скоринг «вино ↔ профиль» и подбор. Профиль приходит в каждом
запросе целиком (сервис не хранит состояние).

| Эндпоинт | Вход | Выход |
|---|---|---|
| `POST /v1/chat` | `{messages: [{role, content}], profile}` | `{reply, profile, picks, suggestions}` — реплика, обновлённый профиль, подборка, подсказки |
| `POST /v1/recommend` | `{profile, k, exclude[]}` | `{profile, picks}` — подборка под профиль |
| `POST /v1/match` | `{slug, profile}` | `{wine, score, verdict, reasons[]}` — соответствие конкретного вина профилю |
| `POST /v1/match_many` | `{slugs[], profile}` | `{items[]}` — то же для списка (до 50), порядок сохраняется |
| `POST /v1/analogs` | `{slug, k}` | `{picks}` — похожие вина других виноделен |
| `POST /v1/stt` | `multipart`: `audio` | `{text}` — расшифровка голоса |
| `GET /v1/wine/{slug}` | — | атрибуты вина для карточки (цвет, сладость, игристость, сорта, блюда, описание) |
| `GET /v1/vocab` | — | словари значений: цвета, сладость, группы блюд, регионы |
| `GET /health` | — | `{status, wines, llm_model, stt_model, api_key}` |

Ошибки: `404` — неизвестный slug; `502` — внешняя модель недоступна или вернула ошибку;
`400` — пустое или слишком большое аудио.

`api_key: false` в `/health` означает, что не задан `OPENROUTER_API_KEY`: диалог и распознавание
речи работать не будут, остальные эндпоинты (скоринг, подбор, аналоги) — работают.

## Как это связано

```
браузер ──► web :3000 ──┬─► ml :8080        распознавание (фото → вино)
                        └─► sommelier :8090 диалог, речь, скоринг, аналоги
                                   └─► db :5432  профили вин
```
