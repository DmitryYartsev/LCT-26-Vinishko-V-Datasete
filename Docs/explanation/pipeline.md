# Обработка запроса: этапы и участники

Страница описывает, что происходит с фотографией от загрузки до ответа: какие этапы проходит
запрос, какие данные на каждом из них используются и на каком основании принимается решение.

## Этап 1. Нормализация изображения

Детектор бутылки определяет её положение на снимке и вырезает с небольшим запасом по краям. Это
исключает из дальнейшей обработки фон и посторонние объекты.

Из полученного кропа второй детектор выделяет этикетку. Если этикетка не найдена, вторым
изображением становится кроп бутылки.

Результат этапа — два изображения: бутылка и этикетка.

## Этап 2. Вычисление признаков

Каждое изображение преобразуется энкодером (SigLIP2) в вектор из 768 чисел единичной длины.
Для всех фотографий каталога такие векторы вычислены заранее — отдельно по кропу бутылки
и по кропу этикетки.

## Этап 3. Поиск по индексу

Вектор запроса сравнивается с векторами каталога по косинусному сходству. Выполняются два
независимых поиска: по кропу бутылки (ключ индекса `…siglip2-base-patch16-256`) и по кропу
этикетки (ключ `…siglip2-base-patch16-256#label`).

У каждого вина в базе несколько векторов — по одному на каталожное фото, — поэтому результат
поиска агрегируется по вину: остаётся лучший вектор. Ответом является список вин, а не список
изображений.

## Этап 4. Выбор ветки поиска

Сравнивается сходство первого кандидата в двух ветках; вся дальнейшая обработка использует ветку
с большим значением. Выбор по лучшему результату обусловлен разной природой ошибок: кроп
этикетки точнее различает близкие вина, кроп бутылки надёжнее, когда этикетка не найдена или
обрезана.

## Этап 5. Формирование шорт-листа

Кандидатов отбирает только визуальный поиск: шорт-лист — это первые `top_k` кандидатов победившей
ветки (по умолчанию 6). Модели, читающие текст, в отборе кандидатов не участвуют.

Отсюда важное следствие: если нужного вина нет в шорт-листе, последующие этапы его не вернут.
Поэтому качество поиска измеряется метрикой recall@K — долей запросов, в которых верный ответ
вошёл в первые K позиций. На используемом наборе для оценки recall@30 ≈ 0.97, то есть остальные
запросы не могут быть исправлены последующей обработкой.

## Этап 6. Чтение текста этикетки

Близкие вина одной линейки (разные год, сахар, сорт) на снимке различаются слабо, поэтому
визуальный поиск может поставить первым другое вино. На этикетке эти различия указаны текстом.

Если сходство первого кандидата выше верхнего порога, текст не читается: такого сходства
достаточно. В остальных случаях кроп этикетки отправляется внешней vision-модели, которая
извлекает поля: винодельня, сорт, цвет, сахар, тип, линейка, год, дополнительный текст.

Если прочитано слишком мало (нет ни винодельни, ни сорта) или сорт отсутствует в каталоге,
выполняется второй проход — по кропу бутылки, и поля двух проходов объединяются.

Чтение можно отключить (`ocr.enabled: false`); тогда ответ формируется только визуальным поиском.

## Этап 7. Сопоставление прочитанных полей с каталогом

Сопоставление выполняет не отдельная модель, а детерминированный алгоритм:

1. Для каждой записи каталога вычисляется уверенность — насколько её карточка совпадает
   с прочитанными полями. Наибольший вес имеют сорт и линейка: именно они различают близкие
   вина. Год имеет минимальный вес, так как вино другого года считается тем же вином.
2. Кандидаты сортируются по уверенности. По умолчанию сопоставление идёт по всему каталогу
   (`csv_match.shortlist_only: false`); ограничение шорт-листом доступно настройкой, но повышает
   вероятность «ничьей» между похожими записями.

Это сопоставление полей одной фотографии с записями каталога, а не самостоятельный поиск.

## Этап 8. Замена ответа визуального поиска

Сравниваются две уверенности в одной шкале: уверенность лучшего кандидата по прочитанным полям
и уверенность того ответа, который ранее предложил визуальный поиск. Замена выполняется, только
если выполнены все условия:

* лучший кандидат по полям отличается от текущего ответа визуального поиска (если это то же вино,
  фиксируется согласие — `csv_agrees`);
* его уверенность не ниже порога (`ocr.min_confidence`, `csv_match.min_score`);
* он опережает текущий ответ не менее чем на `csv_match.decision_margin`. Запас необходим, чтобы
  единичная ошибка распознавания (год, цвет, тип) не изменяла ответ.

Если условия не выполнены, ответ визуального поиска сохраняется, а причина указывается в ответе
сервиса: `csv_ambiguous`, `low_csv_confidence`, `no_csv_match`.

## Этап 9. Визуальная проверка предложенной замены

При замене ответа сервис дополнительно сравнивает кроп запроса с фотографией каталога того вина,
которое предложено моделью. Это контроль случая, когда поля прочитаны уверенно, но изображение
относится к другому вину.

По умолчанию эта проверка только диагностическая: значение попадает в ответ
(`visual_similarity`), решение не отменяется. При `visual.block_on_mismatch: true` расхождение
отменяет замену.

## Этап 10. Решение о показе карточки

Последний этап определяет, что увидит пользователь: карточку вина или сценарий «похожие вина».
Сходство первого кандидата делится на три зоны: высокая — карточка показывается сразу; низкая —
«вина в каталоге нет»; промежуточная — карточка показывается только при подтверждении
прочитанным текстом. Подробнее — [catalog-gate.md](catalog-gate.md).

## Кто принимает решения

| Этап | Что определяет | На основании чего |
|---|---|---|
| 3–4 | состав кандидатов | косинусное сходство векторов; побеждает ветка с большим первым результатом |
| 5 | шорт-лист | первые `top_k` кандидатов визуального поиска |
| 6 | набор прочитанных полей | ответ внешней vision-модели по кропу этикетки |
| 7 | порядок кандидатов по полям | детерминированное сопоставление полей с карточками каталога |
| 8 | замена ответа | разница уверенностей в одной шкале и запас `decision_margin` |
| 9 | контроль замены | сходство кропа запроса с фотографией каталога |
| 10 | карточка или «похожие» | три зоны сходства и подтверждение текстом |

## Какие поля ответа соответствуют этапам

| Поле | Этап |
|---|---|
| `branches.bottle`, `branches.label`, `branch` | 3–4 |
| `top1`, `results` | 5 |
| `ocr_fields`, `ocr_input`, `top_candidates` | 6 |
| `csv_confidence`, `csv_margin` | 7 |
| `pre_ocr_slug`, `final_slug`, `stage` | 8 |
| `visual_similarity` | 9 |
| `in_catalog`, `gate_reason`, `confidence.thresholds` | 10 |
| `elapsed_ms` | общее время обработки |
